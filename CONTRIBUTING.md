# Contributing

## Workflow

1. Create a feature branch from `develop`.
2. Keep changes focused and atomic.
3. Add or update tests for behavior changes.
4. Run lint, tests, and build locally before opening a PR.

## Commit Guidelines

- Use clear, scoped commit messages.
- Prefer prefixes like `feat`, `fix`, `docs`, `refactor`, `test`, `chore`.

## Pull Requests

- Describe the problem and solution.
- Link related issues.
- Include test evidence (command output or screenshots when relevant).
- Request review from code owners.

## Code Quality

- Preserve existing project style.
- Avoid unrelated formatting-only changes.
- Do not commit secrets, runtime data, or generated artifacts.
